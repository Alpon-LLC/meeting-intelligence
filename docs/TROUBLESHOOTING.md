# Troubleshooting

- **No Docker daemon/Compose v2:** setup doctor fails. Install/start your own Docker Engine/Desktop; do not mount a production daemon. Docker Desktop must expose the standard socket path to this Compose stack; unsupported rootless/remote sockets require explicit adaptation.
- **Google login fails:** stop duplicate bot submissions. Re-run local login after checking the actual account/session and organization policy. Human handles MFA. No credentials in logs/chat. Browser launch/admission is not guaranteed on every laptop/network.
- **Calendar authorization fails:** check Desktop client, enabled Calendar API, consent-screen test users and matching account. Vexa login is unrelated. Test-mode tokens can expire; authorize again.
- **No eligible event:** timed event, exact Google Meet URL, self not declined, title includes [record], consent flag enabled, current window. Device/process must be running. Check timezone.
- **needs_review:** do not delete state to force another join. Check the exact bot ID using Vexa's authenticated API. A timed-out POST may have succeeded. Reconcile manually before retrying. Same room URL can host different occurrences.
- **No transcript:** wait for real speech and STT warmup; inspect local service health without printing credentials. CPU Whisper can lag. Empty terminal transcripts wait five minutes then stop for review. No invented notes.
- **Summary failed:** transcript stays local. With isolated Hermes activated, run `meeting_app.py summarize <directory>` again. Confirm model auth/budget and generic skill installation. Do not publish model logs containing meeting content.
- **Notion missing permission:** share the exact parent page with the integration. Token alone does not grant page access. No automatic fallback to another destination.
- **Unknown Notion POST result:** inspect your test parent for the exact created page before repairing private/notion receipt. Never repeat a possibly successful POST blindly. The default note title is generic; inspect content and destination.
- **Stopping:** scheduler Ctrl-C does not imply provider teardown. To stop an exact active bot, an authorized operator can call `DELETE /bots/google_meet/<native-code>` with the private API key. Do not put keys in argv or chat; use a local script that reads private/vexa-key. Confirm the same bot ID is terminal via `GET /transcripts/by-id/<id>`. Stopping is an explicit human action, not an offline test.
- **Retention:** Compose down preserves volumes. Local storage contains browser authentication data and signal audio. Use your own encrypted device storage; the local object store uses development root credentials inside the private network, not the bucket-scoped production model. Do not expose its network. Delete only with explicit approval and account for Notion/provider copies separately.
